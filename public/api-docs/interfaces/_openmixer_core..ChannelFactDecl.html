    Optional Readonlycontrol

    control?: FactControl

    What KIND of control carries this fact, in ProcessorParam's own words (number / toggle / enum, plus text for a scribble string). Declared so that "has no declared travel" can be told apart from "has no travel to declare": a mute is a toggle and will never own a min/max, while a pan is a number that simply has not been pointed at its declaration yet. Without this, boundsOf's ledger of unsourced facts can never reach zero, and a ledger that cannot converge stops being read.

    readout is a NUMBER NOBODY WRITES — a meter, an analyser bin. It has a display scale but no allowed values, because there is no door to send one through (meter is owner: { kind: 'none' }). Calling it number would demand a travel that guards nothing; calling it toggle would be a lie about its shape. It is exempt from the provenance ledger for the same reason a mute is: there is no operator input to bound.

    ABSENT means unclassified, not "structured" — a fact whose value is a sub-object or a collection is classified by its RANGE instead: how many sends, members or inserts may exist is declared by the SESSION's allocation (range: { kind: 'allocation' }), which is a provenance answer and not an exemption. A fact nobody has adjudicated yet also reads as absent, and the two are separated by classifying, one fact at a time.

    Optional ReadonlyservedAs

    servedAs?: string

    The path template that SERVES this fact, where it is not /channel/{kind}/{index}/{fact}.

    Absent means the fact's own name IS its sub-path — the default this table's header claims, true for 29 of the 37 facts. The eight that declare a value are served under another name, and BEFORE this column that was indistinguishable from being served nowhere: sourceStereo read as forgotten while its whole value round-trips through the width row, and a gate could not tell the two apart (the 2026-09-01 audit's axis 1, issue #666).

    The value is the MOLD, {kind} and all. Two facts may name the same one — sends and toMain are both instances of the send row, separated by their destination, and parents rides its sibling's members row — so a consumer asking what an ADDRESS may carry takes the UNION of the facts that name it, never one fact's kinds alone.

    It says WHERE, never HOW the row spells the value: the session's own spelling is SNAPSHOT_FIELDS_OF_FACT's concern, and one column answering both would be two questions with one answer.
