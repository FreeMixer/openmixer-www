    Interface HeadAmpRow

    What the /channel/{kind}/{index}/headAmp row PUBLISHES: the record (HeadAmp) plus the preamp's declared GAIN travel.

    The travel is not a fourth stored param — it is the HeadAmpCapability's own HeadAmpGainRange, resolved on every read by headAmpRowOf and never written. It rides the row because the row is where a client already learns everything about this channel's preamp, and because every surface is remote: a client that has to guess how far a knob travels will guess the fabric it was written against. Before this, the surface drew a global 0..55 over an RME mic input that reaches 65 — the top 10 dB unreachable, and nothing in the console able to notice.

    It is a SEPARATE type from HeadAmp on purpose. HeadAmp is the physical record — what the engine applies at the head, what a split shares, what a session persists, and what keyof HeadAmp enumerates as the writable param set. A declaration is none of those; folding it in would make the capability's range a second stored owner of a fact the device declares.

    Optional ReadonlygainDefaultDb

    gainDefaultDb?: number

    The GAIN this preamp comes up at — the box's committing normal gain (import('./head-amp.js').DEFAULT_HEAD_AMP_GAIN_DB), published so a surface's "reset to default" lands on the value the hardware provably arms with, never on a number the client made up. Clients render from what the wire sent; none of them imports the constant.

    Present iff this preamp's travel can hold it (import('./head-amp.js').headAmpGainDefaultOf) — an RME line input's 0..18 declares none. OBSERVED and derived on every read, exactly like gainRange.

    ReadonlygainRange

    gainRange: HeadAmpGainRange

    The travel the patched preamp declares — in the same unit as HeadAmp.gainDb, and bounding it. That was not true before 2026-08-12: the row published a VALUE in dBu beside a RANGE in dB, so -10 sat outside a declared 0..65 and no conformance arm could compare the two. A value and its range in different units have no testable relationship, which is exactly why the divergence went unnoticed for as long as it did.

    OBSERVED, not set: nobody writes this — the device reports it — so OPTIONS marks it writable: false and it rides GET like the values it bounds.
